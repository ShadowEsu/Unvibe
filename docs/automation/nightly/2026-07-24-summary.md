## Backend and sync inspection

### Auth architecture (web/src/)
Three authentication mechanisms:
- **Device code flow** (primary): OAuth-like pairing between desktop and account. Creates device code (`POST /auth/device`), user approves via browser (`POST /auth/approve` with Supabase Google OAuth), desktop polls for token (`POST /auth/token`).
- **Direct email auth** (dev-only): Passwordless email sign-in/sign-up, blocked in production unless `UNCODE_ALLOW_DEV_EMAIL_AUTH=true`.
- **Sealed trial**: Anonymous desktop trial using baked `UNVIBE_TRIAL_TOKEN` with Blob-backed per-install and global monthly limits.

Session handling via `uncode_session` HttpOnly cookie + Bearer token. Token → userId mapping in DB (Supabase) or in-memory Map (MemoryStore).

### Sync architecture
**Event-based, unidirectional (desktop → backend), idempotent by event ID:**
- Desktop records review locally, adds event ID to outbox
- `sync.ts` pushes events via `POST /api/v1/events` (max 500, validated by `eventValidation.ts`)
- Backend upserts with `ON CONFLICT(id)` (Postgres) or `findIndex` (MemoryStore)
- After push: desktop pulls remote history via cursor-based pagination (`?cursor=&limit=200`)
- Merge: local pending events win on conflict; remote body fields merge but `code`/`explanation` stay on-device
- Outbox uses `Set<string>` — multiple mutations to same event only queued once

### Retry, backoff, idempotency

**Desktop sync** (`syncModel.ts:retryDelayMs()`):
- Exponential backoff: 1s → 2s → 4s → ... → capped at 60s
- 20% jitter via `Math.random()`
- Network errors → `'offline'` phase with scheduled retry
- 401/session expired → `'auth_required'` phase, no retry

**Backend idempotency**:
- Event upsert by UUID (silent overwrite on conflict)
- Stripe checkout/seats use Stripe idempotency keys
- Stripe webhooks use `claimWebhook` RPC (atomic claim with retry on failure)
- Usage metering fail-open: returns `{ allowed: true }` on hiccup rather than blocking

### Security boundary verification
- **No Supabase credentials or AI keys in app source** — confirmed via grep for `supabase`, `SUPABASE`, `service_role`, `anon_key` across all `app/src/`
- All network I/O in main process only; renderer has `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`
- Preload bridge exposes only typed IPC calls via `window.unvibe`
- Secret filtering (`secretFilter.ts`) runs before every remote request
- Tokens encrypted at rest with Electron `safeStorage` (OS keychain)
- Stripe provider IDs stripped from client responses by `publicBillingOverview()`

### Storage abstraction
`MemoryStore` (dev, `globalThis`-based) vs `SupabaseStore` (prod, Postgres via service-role key). Selection at startup from env vars. MemoryStore is blocked in production unless `UNCODE_ALLOW_MEMORY_STORE=true`.
